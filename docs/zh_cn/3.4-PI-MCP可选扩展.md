# 3.4 PI MCP 可选扩展

**💡 PI v2.12.0**

本扩展约定 [ProjectInterface V2](3.3-ProjectInterfaceV2协议.md) Client 如何通过 [Model Context Protocol（MCP）](https://modelcontextprotocol.io/specification/latest) 提供项目任务。资源作者继续编写 PI；Client 负责将 PI 和现有运行流程映射为 MCP 工具；AI 工具作为 MCP 客户端调用。

## 范围与启用

目标是让 AI 发现项目已有的任务、理解选项、按用户要求运行任务，并查询或停止本次运行。MCP 是 **Client 的可选能力**：不实现本扩展的 Client 仍然可以完整支持 PI，资源项目也不需要声明或实现 MCP 服务。

- 不新增顶层 `mcp` 字段，不改变 `interface_version: 2` 或现有 Schema。资源配置不得自动开启服务或授予控制权限。
- 服务默认关闭，由用户在 Client 中显式启用。Client 应允许用户分别控制任务执行和截图权限；关闭的能力不得出现在 `tools/list` 中，调用时也必须校验权限。
- 支持本扩展的 Client 实现下文六个核心工具；用户未授予执行权限时，仅暴露其中的四个查询工具。`capture_screen` 是独立可选工具，不影响核心工具的符合性。
- 不要求标签页、可编辑队列或独立 Web 服务；不统一端口、SDK、前后端桥接方式或 Client 配置文件格式。
- 本版不提供持久任务列表增删改、切换设备/资源、安装/更新、任意 Pipeline 覆盖、Shell、点击或滑动工具。项目已声明的任务仍可能执行程序或操作设备，执行授权应覆盖其正常启动流程，包括 `pretask` 和 Agent。

任务参数只作用于本次运行，不改写用户保存的任务列表、选项或预设。需要这些产品功能的 Client 可提供其他工具，但不能将其作为本扩展的前提。

## 传输与 MCP 行为

沿用 MCP 的初始化、协议版本协商、`tools/list`、`tools/call` 和错误机制，不定义另一套 JSON-RPC 协议。Client 可提供 stdio 或 Streamable HTTP；在连接说明中明确传输方式和连接参数，不指定全生态共用的固定端口。

HTTP 服务默认仅监听回环地址，校验对端与 Host，并按 MCP 传输安全要求校验 Origin；未授权的浏览器来源必须拒绝。非本机部署的认证、授权与传输保护不属于本版约定，不能仅通过改为监听所有地址来提供远程访问。stdio 不能把日志混入协议输出。

每个工具必须提供准确的 `inputSchema`；JSON 结果使用 `structuredContent`，并在 `content` 中提供同一对象的紧凑 JSON 文本，便于兼容只读取文本的 MCP 客户端。若声明 `outputSchema`，成功结果必须符合它。截图使用 MCP image content。

工具名和机器字段不翻译，`label`、`description`、工具标题和错误消息可本地化，PI 的 `$` 字符串应先解析。描述文本、日志和截图都是数据，不能赋予其额外权限。

## 实例、版本与标识符

`instance` 是 Client 已配置的运行上下文：绑定一个项目、选中的控制器、目标设备、资源和本地参数。它可以对应一个 CLI 配置或 UI 标签页，但不要求存在图形界面。

| 字段 | 约定 |
| --- | --- |
| `pi_mcp_version` | 本文定义的工具约定版本，固定为字符串 `"1.0"`，与 MCP 传输协议版本、PI JSON 主版本分别标识 |
| `instance_id` | Client 生成的不透明非空字符串；同一服务生命周期内不复用，实例移除后失效，服务重启后生成新标识 |
| `context_revision` | 不透明非空字符串；项目/导入、控制器或目标设备配置、资源及影响运行的本地选项、预任务或凭据发生变化时更新 |
| `run_id` | Client 为每次已接受的运行生成的非空字符串；同一实例生命周期内唯一，不使用 MaaTaskId 代替 |
| `request_id` | MCP 调用方为一次启动意图生成的非空字符串，用于重试去重；不是 JSON-RPC 的消息 ID |
| `name` / `option_key` | 使用 PI 的 `task.name`、`case.name`、输入字段 `name` 和 `option` 键，不使用显示名称或数组下标 |

除 `list_instances` 外，所有工具必须显式传入 `instance_id`，不得回退到当前焦点、首个实例或其他设备。不同项目即使 `name` 相同，也由实例区分。服务重启后，调用方必须重新发现实例。

每个实例对同一 `task.name` 必须能给出唯一的基础参数，未配置时可使用 PI 默认值；不得猜测同名 UI 队列条目。无法确定所需参数时返回 `configuration_required`。参数描述与启动校验必须使用同一套规则，且基础参数变化必须更新 `context_revision`。

## 核心工具

下表中的参数均为必填，标记 `?` 的除外。对象字段使用下划线命名，未知参数应拒绝。所有查询工具均不得连接设备、启动预任务、加载运行资源或执行任务。

| 工具 | 参数 | 成功结果及语义 |
| --- | --- | --- |
| `list_instances` | 无 | `{pi_mcp_version, instances}`；每个实例包含 `instance_id`、`project`（`name`、可选 `label` / `version`）、`controller`（PI `name` 或 `null`）、`resource`（PI `name` 或 `null`）、`context_revision`、布尔值 `connected` / `busy`、`active_run_id`（字符串或 `null`） |
| `list_tasks` | `instance_id`、`cursor?`、`limit?` | `{context_revision, tasks, next_cursor}`；列出当前控制器/资源适用的 PI 任务，条目包含 `name`、可选 `label` / `description` / `group` |
| `describe_task` | `instance_id`、`task_name`、`option_key?`、`cursor?`、`limit?` | `{context_revision, task_name, root_options, options, next_cursor}`；返回下文定义的选项描述；指定 `option_key` 时仅返回该选项 |
| `start_tasks` | `instance_id`、`context_revision`、`request_id`、`tasks` | `{run_id, state}`；`tasks` 是非空有序数组，每项为 `{name, option?}`；校验并接受一次参数快照，异步启动，立即返回运行标识 |
| `stop_tasks` | `instance_id`、`run_id` | `{run_id, state}`；请求停止指定运行；可返回 `stopping`，不将“已发停止请求”当成“已经停止” |
| `get_run_status` | `instance_id`、`run_id`、`after?`、`limit?` | `{run_id, state, tasks, logs, next_cursor, logs_truncated, error?}`；查询指定运行，包括启动阶段的失败 |

`list_tasks` 按合并后的 PI 顺序返回任务，只包括 PI `task`；`pretask` 随正常启动流程处理，不作为普通任务暴露，Client 自有特殊任务也不混入。

`busy` 包括由 Client 其他入口发起的启动、运行和停止；`active_run_id` 指当前可通过本扩展查询的运行，没有时为 `null`。本扩展不强制为其他入口的运行补建运行记录，因此 `busy: true` 与 `active_run_id: null` 可以同时出现，仍须拒绝新的启动。

分页中的 `limit` 为整数，范围 `1..100`，默认 `50`。`cursor` 为不透明字符串，`next_cursor: null` 表示结束。游标绑定实例、查询参数与上下文版本；版本变化或游标失效时返回 `stale_context`，调用方从头读取，不得悄悄漏项。`describe_task` 的分页只用于指定 `option_key` 的 case 列表，未指定时不得传 `cursor`。

## 选项描述与参数

`root_options` 是任务的 `task.option` 键数组；`options` 是以键索引的描述表，每个适用且可从任务到达的选项至多出现一次，不能递归复制整棵树。控制器/资源过滤遵守 PI 规则。

选项描述包含 `type`（补全 PI 缺省的 `select`）、可选 `label` / `description`、脱敏后的基础取值 `value`，以及适用于该类型的以下字段：

- `select` / `switch` / `checkbox`：`case_count`；`checkbox` 还包含已声明的 `min_count` / `max_count`。默认不展开 `cases`；指定 `option_key` 时分页返回 `cases`，每项包含 `name`、可选 `label` / `description` 和子配置项键数组 `option`。不支持用标签替代 `case.name`。
- `input`：`inputs`，保留字段的 `name`、`label`、`description`、`pipeline_type`、`verify`、`pattern_msg`、`password`、`input_type` 和非密码的 `default`。
- `hotkey`：`hotkeys`，保留 PI 中的字段说明与字符串默认值。

指定的 `option_key` 必须可通过该任务的根选项及 case 子选项到达，不能借此读取项目中无关选项。case 引用只传键；有环时也不能无限展开。无 case 分页时 `next_cursor` 为 `null`。

`start_tasks.tasks[].option` 沿用 PI `preset.task[].option` 的值格式：

| 类型 | 值 |
| --- | --- |
| `select` / `switch` | `case.name` 字符串；switch 使用实际声明的 Yes/No case 名称，不另定义布尔转换 |
| `checkbox` | `case.name` 字符串数组，不得重复；覆盖顺序仍按 PI 的 `cases` 定义顺序 |
| `input` | 字段 `name` 到字符串的对象；即使 `pipeline_type` 为 `int` / `bool` 也先传字符串 |
| `hotkey` | 快捷键字段 `name` 到快捷键字符串的对象，不传虚拟键码 |

以 `describe_task` 给出的基础取值为起点：省略的 option 和输入字段保持基础值；传入的 select/switch/checkbox 值整体替换，input/hotkey 按字段合并。子配置项以其自身键放在同一 `option` 对象中，不嵌入父值。

Client 必须先生成完整候选参数，再按最终选择计算子选项激活状态并校验，不得依赖 JSON 键顺序。未知任务、选项、字段、case、类型不匹配、重复 checkbox 值、数量限制、正则或类型转换失败，以及显式传入不适用/未激活的选项，均拒绝整个请求，不部分执行。

全局、资源和控制器级选项以及预任务沿用实例已有配置；本工具不提供其修改接口。正常的 PI 过滤、合并优先级、资源完整性校验和 Agent 环境变量约定继续生效。

### 密码字段

所有结果（包括基础取值、字段默认值、错误和日志）必须省略 `password: true` 的值，保留字段的 `password` 标记。不得返回密文或可回写的掩码占位符；也不得通过其他原始 PI / Pipeline 数据绕过此限制。

本版拒绝通过 MCP 设置密码字段，返回 `sensitive_option`；省略时保留本地已配置的凭据。运行所需凭据未配置时返回 `configuration_required`，引导用户在 Client 的本地配置渠道填写，不要求在 AI 对话中提供。非法 PI 即使含密码 `default`，也不得将其回传。

## 运行生命周期

`state` 的值为：

| 状态 | 含义 |
| --- | --- |
| `starting` | 已接受；正在准备、执行预任务、连接设备或加载资源，尚未开始任务序列 |
| `running` | 正在执行请求中的任务序列 |
| `stopping` | 已请求停止，正在取消启动流程或等待当前任务安全结束 |
| `succeeded` | 所有请求任务成功完成，终态 |
| `failed` | 启动或任务执行失败，终态 |
| `stopped` | 已停止，且该运行不会再提交任务或执行后续启动步骤，终态 |

所有终态都要求该运行的启动与执行工作已结束，不能仍有会继续提交任务的后台流程。正常移除实例前须完成其运行的停止与清理，不能令尚在运行的标识提前失效。

### 接受与启动

1. 在同一实例的临界区内完成权限、版本、任务和参数校验，取得不可变快照并登记 `run_id`，然后再启动异步工作。校验失败不创建运行，也不产生设备/程序副作用。
2. 快照包含有序任务、完整有效参数、预任务、本地凭据与控制器/资源配置。接受后修改本地配置不得改变本次运行；后续请求应读取新版本。
3. 同一实例从接受起到进入终态只允许一个运行。MCP、界面、快捷键和定时启动必须共用该限制；不同实例独立，不能因 A 正在停止而忽略 B 的停止请求。
4. 启动复用 Client 正常的权限检查、预任务、连接、资源加载与 Agent 流程，但执行请求的快照，不能悄悄改成执行 UI 勾选列表。不得经 MCP 自动提权；需要额外用户操作时运行失败并报告原因。
5. 按 `tasks` 数组顺序执行，每项的 `option` 单独生效；允许同名任务以不同参数显式出现多次。任何一项失败则不再启动后续项，整次运行进入 `failed`。
6. `start_tasks` 不等待连接、资源加载或任务完成。接受后的启动失败通过同一 `run_id` 查询，不能变成失去归属的后台任务。

`context_revision` 必须与当前实例匹配，否则返回 `stale_context`。版本应由 Client 分配，不通过对密码取公开哈希来生成。

### 重试与停止

Client 按 `(instance_id, request_id)` 去重：完全相同的启动参数重试返回同一 `run_id` 和当前状态，即使运行已结束也不再次执行；同一标识配不同参数返回 `request_conflict`。比较忽略对象键顺序，但保留数组顺序。

去重查询必须先于新的版本/忙碌状态检查，重试已经接受的请求不能因之后的上下文变化而误报为一次新请求。权限仍须每次校验。同一实例生命周期内保留去重映射、运行标识和终态；日志可以有界保留。达到容量限制时拒绝新的启动并返回 `resource_exhausted`，不得通过遗忘旧标识使重试重新执行。

停止按 `run_id` 定位。已结束的运行返回原终态；旧运行的停止请求不能停止该实例后来的运行。停止 `starting` 的运行必须取消其后续启动步骤，不能只停止尚未提交任务的 Tasker。

只有启动流程已退出、相关预任务/执行工作已结束且不会再提交后续任务时才能报告 `stopped`。不能立即安全结束时保持 `stopping` 并允许查询，不得提前返回“停止成功”。停止不能撤销已发生的设备操作或外部程序副作用。

连接断开、工具超时或 MCP 请求取消均不表示运行已取消。调用方用相同 `request_id` 恢复启动结果，或查询/显式停止对应 `run_id`；不得换一个标识盲目重试。

去重不跨服务重启。旧 `instance_id` 失效时应重新发现并核实先前运行结果，不得换用新实例标识自动重放结果未知的启动请求。

### 状态与日志

`get_run_status.tasks` 按请求顺序返回 `{index, name, state, option}`，`index` 从零开始，区分同名任务；`option` 是本次快照中脱敏后的完整任务级参数。条目状态为 `pending` / `running` / `succeeded` / `failed` / `stopped` / `skipped`；因启动/前项失败或停止而未执行的项为 `skipped`。运行失败时必须提供脱敏的 `error`（见下文）。

日志条目为 `{cursor, level, message}`，`cursor` 是不透明字符串，`level` 为 `debug` / `info` / `warning` / `error`。`after` 为同一运行的日志游标：省略时取最近的日志，指定时取其后的日志。`limit` 默认 `20`，范围 `1..100`。`next_cursor` 表示本次读到的位置，尚无日志时为 `null`；日志被裁剪导致缺口时设置 `logs_truncated: true`，不能伪装为完整记录。

Client 应在本地记录来源为 MCP 的启动/停止、实例与运行标识及任务名称，不记录完整请求、凭据或截图内容。日志读取只限该运行，不暴露任意文件读取接口。

## 可选截图工具

`capture_screen({instance_id})` 仅在 Client 支持且用户授权时暴露。只截取该实例已连接的设备；未连接返回 `not_connected`，不得为取图而自动连接或启动任务。

成功时在 `content` 中返回 `image/png` 的 MCP image block，并附同一结果对象的 JSON 文本；`structuredContent` 为 `{instance_id, captured_at, width, height}`。`captured_at` 是带时区的 RFC 3339 时间，宽高为返回图像的像素尺寸。不返回本地文件路径，不把图像 base64 塞进 JSON 字段。画面是实时观察，不能声称它与某条日志或某个节点严格同步。

## 错误与工具提示

业务失败使用 MCP `CallToolResult` 的 `isError: true`，JSON 对象为 `{error: {code, message, path?}}`；`get_run_status.error` 使用同一内层对象，运行进入 `failed` 是一次成功的状态查询。未知工具、无效工具参数形状等使用 MCP 标准协议错误。

稳定错误码包括 `instance_not_found`、`task_not_found`、`option_not_found`、`invalid_option`、`sensitive_option`、`configuration_required`、`stale_context`、`instance_busy`、`request_conflict`、`run_not_found`、`not_connected`、`permission_denied`、`resource_exhausted` 和 `execution_failed`。`path` 为可选的 JSON Pointer，例如 `/tasks/0/option/Stage/chapter`。错误可说明合法 case 名称或约束，但不得回显密码或完整请求。执行阶段的失败使用 `execution_failed` 或上表适用的具体错误码。

查询工具应标记 `readOnlyHint: true`；`start_tasks` 为 `readOnlyHint: false`、`destructiveHint: true`、`idempotentHint: true`、`openWorldHint: true`，其中幂等性依赖必填 `request_id`。`stop_tasks` 标记 `readOnlyHint: false`、`idempotentHint: true`、`openWorldHint: true`。annotations 仅是提示，不代替权限校验。

## 调用示例

以下示例只展示工具参数或 JSON 结果，不重复 MCP 外层封装。假设实例已配置好控制器、资源及所需的本地凭据。

从 `list_instances` 获得明确的目标：

```json
{
    "pi_mcp_version": "1.0",
    "instances": [
        {
            "instance_id": "instance-a",
            "project": {"name": "ExampleProject", "version": "1.0.0"},
            "controller": "Android",
            "resource": "Official",
            "context_revision": "revision-7",
            "connected": false,
            "busy": false,
            "active_run_id": null
        }
    ]
}
```

调用 `list_tasks` 和 `describe_task` 后，按真实的名称与选项发起一次运行：

```json
{
    "instance_id": "instance-a",
    "context_revision": "revision-7",
    "request_id": "client-intent-42",
    "tasks": [
        {
            "name": "FarmStage",
            "option": {
                "Mode": "Manual",
                "Stage": {"chapter": "4"},
                "Features": ["AutoBattle", "Collect"]
            }
        }
    ]
}
```

`start_tasks` 接受后返回：

```json
{"run_id": "run-12", "state": "starting"}
```

后续调用 `get_run_status`；需要停止时对同一运行调用 `stop_tasks`，两者的最小参数均为：

```json
{"instance_id": "instance-a", "run_id": "run-12"}
```
