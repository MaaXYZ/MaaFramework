# Custom & Agent

## Custom

Custom 是框架提供的扩展机制，允许开发者实现框架内置识别算法和动作类型无法满足的特殊需求。

1. 自定义识别 (Custom Recognition)

    当内置的识别算法（如 TemplateMatch、FeatureMatch、OCR 等）无法实现特定的图像识别需求时，可以使用自定义识别方法。

2. 自定义动作 (Custom Action)

    当内置的动作类型（如 Click、Swipe、InputText 等）无法完成特定的操作需求时，可以执行自定义动作。

主流的编写 Custom 的方法分为两种。

- 通过UI注册 Custom 的方法请见各 UI 的手册

- 通过 Agent 注册 Custom 的方法请见：[Agent](#agent) （⭐ 推荐）

在 Pipeline 中调用 Custom 的方法请参考[任务流水线协议](3.1-任务流水线协议.md)。

## Agent

当你需要某些难以用 Pipeline 实现的自定义识别或自定义动作时，Agent 提供了一种更稳妥的扩展方式。

- **提高稳定性**：自定义代码与框架核心隔离，降低因自定义逻辑导致整体失败的风险。
- **便于扩展**：适合承载较复杂、可独立迭代的业务逻辑。
- **更易维护**：框架升级与自定义实现的边界更清晰。
- **多种语言支持**：可自行选择支持的编程语言，并利用该语言的特性。

### AgentClient 和 AgentServer

#### AgentServer

AgentServer 用于注册并执行你编写的自定义识别与自定义动作代码。通常用于实现较复杂的 *识别判断* 或 *业务动作*，以及实现 *事件监听*。它更专注于业务能力本身，而不是主流程调度与框架生命周期管理。

一个简单的 AgentServer 示例参考可见 [模板 Commit](https://github.com/MaaXYZ/MaaPracticeBoilerplate/commit/126a56cefc17bf6c8335c703387d8d3ee2dad4d1)。

#### 什么时候需要编写 AgentServer ？

> [!NOTE]  
> 通常语境下，如果没有特别指明，在社区交流中提到 Agent 一般指的是 AgentServer 。

通常建议在以下场景考虑编写：

- 自定义识别/动作逻辑较复杂，用 Pipeline 实现较为复杂。
- 自定义识别/动作需要特殊的逻辑或是涉及到算法，无法用 Pipeline 实现。

#### AgentClient

AgentClient 是 [UI](./1.2-术语解释.md) 的一部分，其负责与 AgentServer 进行通信。在主流程执行到自定义节点时，AgentClient 会把请求交给 Server，并在对侧执行完成后接收结果，再将结果带回主流程继续执行。它负责把调用链路衔接起来，但本身并不承载具体业务规则。

## 自定义控制器

设备有自己的截图或输入接口时，可以把它接入 MaaFramework 的 Controller。宿主按名称创建控制器，调用 `post_connection()` 连接设备，再用 `tasker.bind(resource, controller)` 绑定到任务。Pipeline 中已有的识别和 `Click` 等动作即可使用这个设备。

### 由 Agent 提供设备

每个注册名称对应 Agent 进程中的一个设备实例。宿主通过 IPC 或本机 TCP 连接 Agent，取得该会话的设备名称列表，再选择一个名称创建代理。多个同名代理共用服务端设备的状态。控制器请求走独立通道，因此同一 Agent 的自定义动作可以等待控制器完成输入或截图。只提供控制器的 Agent 可以直接连接。如果还注册了自定义识别或动作，宿主需要在连接前用 `client.bind(resource)` 指定注册目标。

下面的 `controller_agent.py` 提供一块内存画布。点击后，该位置的像素会变为白色。`get_features()` 返回 0 让框架直接调用 `click`。在自己的设备上，可以把 `screencap` 和 `click` 换成设备 SDK 的实际调用。

```python
import sys

import numpy as np
from maa.agent.agent_server import AgentServer
from maa.controller import CustomController


@AgentServer.custom_controller("canvas")
class Canvas(CustomController):
    def connect(self):
        self.frame = np.zeros((720, 720, 3), dtype=np.uint8)
        return True

    def request_uuid(self):
        return "canvas-1"

    def get_features(self):
        return 0

    def click(self, x, y):
        self.frame[y, x] = 255
        return True

    def screencap(self):
        return self.frame


if not AgentServer.start_up(sys.argv[1]):
    raise RuntimeError("Agent startup failed")
AgentServer.join()
AgentServer.shut_down()
```

将宿主脚本放在同一目录中运行。第一次截图建立坐标映射，第二次截图验证点击已经在服务端生效。任务执行期间保持 Agent 连接。断开后重新连接时，需要重新创建代理。

```python
import subprocess
import sys
from pathlib import Path

from maa.agent_client import AgentClient

client = AgentClient()
client.set_timeout(10000)
server = Path(__file__).with_name("controller_agent.py")
child = subprocess.Popen([sys.executable, str(server), client.identifier])
try:
    assert client.connect()
    assert "canvas" in client.custom_controller_list
    controller = client.create_custom_controller("canvas")
    assert controller.post_connection().wait().succeeded
    assert controller.post_screencap().wait().succeeded
    assert controller.post_click(20, 30).wait().succeeded
    image = controller.post_screencap().wait().get()
    assert image[30, 20].tolist() == [255, 255, 255]
finally:
    if client.connected:
        client.disconnect()
    elif child.poll() is None:
        child.terminate()
    child.wait()
```

### 由原生插件提供设备

插件在宿主进程内运行。编译插件时定义 `MAA_PLUGIN_EXPORTS`，包含 `MaaPlugin/MaaPluginAPI.h` 和 `MaaFramework/MaaAPI.h`，并链接 `MaaFramework`。使用插件 v1 接口（`GetApiVersion()` 返回 1），通过 C 链接导出以下两个函数。

```c
MAA_PLUGIN_API const char* GetCustomControllerName(void);
MAA_PLUGIN_API MaaController* CreateCustomController(const char* config_json);
```

前者返回稳定、非空的 UTF-8 名称，例如 `"PixelDevice"`。后者读取插件自定义的 JSON 配置，每次成功调用都返回一个归宿主所有的新控制器，创建失败时返回 `NULL`。如果设备状态需要随控制器释放，可用 `MaaCustomControllerCreateWithRelease` 把回调表、设备指针和释放函数组合成控制器。仅监听事件的 v1 插件继续按原方式加载。

在宿主进程创建任何 Resource、Controller 或 Tasker 之前加载插件。插件关闭后，工厂也会停止接受新的创建请求。

```python
from maa.controller import PluginController
from maa.tasker import Tasker

assert Tasker.load_plugin("./ControllerFixture.so")
assert "PixelDevice" in PluginController.list_names()
controller = PluginController("PixelDevice", {"device": "device-1"})
assert controller.post_connection().wait().succeeded
```
