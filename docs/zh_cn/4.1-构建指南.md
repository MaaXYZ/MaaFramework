# 4.1 构建指南

> [!TIP]
> _仅当您准备开发 MaaFramework 本身时，才需要阅读本章节内容。若您仅希望基于 MaaFramework 开发自己的应用，则请参考 [快速开始](1.1-快速开始.md)。_

开始前，请确保已安装 Git、Python 3、CMake 3.24+，以及对应平台的编译链（Windows: MSVC 2022；Linux/macOS: Ninja + g++/clang）。

## 本地开发

1. 完整克隆本仓库及子模块（推荐一次性同步）  
    子模块包含第三方依赖，构建前必须初始化，可重复执行以保证同步。

    ```sh
    git clone --recurse-submodules https://github.com/MaaXYZ/MaaFramework.git
    ```

    或

    ```sh
    git clone https://github.com/MaaXYZ/MaaFramework.git
    cd MaaFramework
    git submodule update --init --recursive
    ```

2. 下载 MaaDeps prebuilt

    ```sh
    python3 tools/maadeps-download.py
    ```

    脚本会自动下载并校验预编译依赖，如遇网络问题可重复执行。

3. 配置 CMake 预设

    iOS 控制器默认启用，配置前请先按 [构建 iOS 支持](#构建-ios-支持) 准备额外依赖；无需 iOS 时传 `-DWITH_IOS_CONTROLLER=OFF`。

    - Windows

    ```bash
    cmake --preset "MSVC 2022"
    ```

    - Linux

    ```bash
    # 根据实际情况择一执行
    cmake --preset "NinjaMulti Linux x64"
    # 或者
    cmake --preset "NinjaMulti Linux arm64"
    ```

    - macOS

    ```bash
    cmake --preset "NinjaMulti"
    ```

4. 构建并安装

    ```bash
    cmake --build build --config Release
    cmake --install build --prefix install
    ```

根据需要可将 `--config` 切换为 `Debug`/`RelWithDebInfo`。生成的二进制及相关文件默认位于 `install` 目录。

详情请参考 [Build CI](https://github.com/MaaXYZ/MaaFramework/blob/main/.github/workflows/build.yml) 。

## 构建 iOS 支持

iOS 控制器默认启用。配置 CMake 前，除 MaaDeps 外还需准备以下目标平台依赖：

| 依赖 | 用途及要求 |
| --- | --- |
| OpenSSL | 配对、加密及 USB/Wi-Fi 认证 |
| FFmpeg（可选） | `avcodec`、`avutil`、`swscale`，启用 HEVC、PNG 解码及像素转换 |
| libcurl | DDI 下载及签票 HTTPS；macOS 使用 SDK 提供的 libcurl |
| pugixml | plist XML 解析 |
| lwIP、mDNS | 用户态隧道网络及设备发现 |

JSON 使用项目内的 meojson。pugixml 可通过 CMake 包提供；缺少时与 lwIP、mDNS 一样按锁定 URL 和哈希获取源码。
使用 `-DMAA_IOS_FETCH_DEPENDENCIES=OFF` 禁止这些 CMake 下载；此时需提供 pugixml 包或
`FETCHCONTENT_SOURCE_DIR_PUGIXML`，以及 `FETCHCONTENT_SOURCE_DIR_LWIP`、`FETCHCONTENT_SOURCE_DIR_MDNS`。
OpenSSL 和非 macOS 的 libcurl 需要预先构建或安装；使用 FFmpeg 时同样需要预先准备。CMake 不会自动下载这些库。

### 使用仓库依赖配方

[`tools/ios/ci/dependencies.py`](../../tools/ios/ci/dependencies.py) 使用仓库的 vcpkg 清单构建依赖，生成供框架配置使用的 `framework.cmake`。
`--platform` 支持 `windows`、`linux`、`macos`、`android`，`--architecture` 支持 `x86_64`、`aarch64`。
先下载对应目标的 MaaDeps，并准备已 bootstrap 的 vcpkg；版本固定在
[`tools/ios/ci/vcpkg.json`](../../tools/ios/ci/vcpkg.json) 的 `builtin-baseline`。

以下示例在 Apple Silicon macOS 上从仓库根目录执行：

```bash
git clone https://github.com/microsoft/vcpkg.git build/ios-vcpkg
git -C build/ios-vcpkg checkout e456309491fd875487bf02b8a0dca76c1b1b00cc
build/ios-vcpkg/bootstrap-vcpkg.sh -disableMetrics
python3 tools/ios/ci/dependencies.py \
    --vcpkg "$PWD/build/ios-vcpkg" \
    --work "$PWD/build/ios-dependencies" \
    --platform macos --architecture aarch64
cmake -C build/ios-dependencies/framework.cmake --preset NinjaMulti \
    -DWITH_IOS_CONTROLLER=ON
cmake --build build --config Release --parallel
cmake --install build --config Release --prefix install
```

Windows 使用 `bootstrap-vcpkg.bat`。其他目标需选择对应的平台、架构和框架 CMake 预设。
Linux 配方使用 MaaDeps 的目标工具链与 sysroot；Android 配方要求 `ANDROID_NDK_ROOT`，使用 API 24。
macOS 框架及此配方中的依赖均以 13.3 为部署目标；使用面向较新系统构建的 Homebrew 库，不能证明产物兼容 13.3。
交叉编译必须使用目标架构的依赖，不能混入宿主机库。

无需 iOS 时设置 `-DWITH_IOS_CONTROLLER=OFF`；框架配置不查找或下载 iOS 专用依赖。
默认自动检测可用的 FFmpeg；设置 `-DMAA_IOS_USE_FFMPEG=OFF` 可跳过其查找和链接。
不带 FFmpeg 时，macOS 保留 VideoToolbox 视频解码，但没有软件解码兜底；Windows、Linux 和 Android 仅保留 `ScreenshotService`。发现接口按实际编译能力返回取图方法。
依赖构建配方和官方 CI 构建仍包含 FFmpeg，以提供完整的视频支持。

### 测试和发行包

- `-DBUILD_IOS_CONTROLLER_TESTING=ON` 构建控制器及 Toolkit 离线测试；`-DMAA_IOS_PROTOCOL_TESTS=ON` 构建协议测试。
- 构建后执行 `ctest --test-dir build -C Release --output-on-failure`。离线测试不代替真实设备验收。
- 框架 [`build.yml`](../../.github/workflows/build.yml) 为 Windows、Linux、macOS 和 Android 构建及打包依赖；
  [`test.yml`](../../.github/workflows/test.yml) 在 Windows x64、Linux x64、macOS arm64 上运行 iOS 原生及 Python 离线测试。
- 发行时通过 [`tools/ios/ci/package.py`](../../tools/ios/ci/package.py) 收集所需运行库、许可证、对应源码及构建配方。
  参数和调用顺序参照 `build.yml` 的 `Collect iOS runtime dependencies and source materials` 步骤。

## Android 主机的 iOS 视频流

Android arm64 主机可通过 FFmpeg 软件解码使用 iOS `Stream` 取图；当前不使用 MediaCodec。
未提供目标平台 FFmpeg 时仍可只构建 `ScreenshotService`。发现接口按共享协议目标的实际编译能力返回取图方法。

先准备 Android NDK、arm64 Android MaaDeps 和 `make`，从仓库根目录构建额外依赖：

```bash
export ANDROID_NDK_ROOT=/path/to/android-ndk
export ANDROID_API=24
export WORK_DIR="$PWD/build/android-deps/src"
bash tools/ios-android-deps.sh -j 6 "$PWD/build/android-deps/out"
```

脚本固定下载并校验 OpenSSL、curl 和 FFmpeg 源码；FFmpeg 只启用 HEVC/PNG 解码与像素转换，
生成 `libavcodec.so`、`libavutil.so`、`libswscale.so`。不启用 GPL/nonfree 组件。
源归档保存在 `WORK_DIR`，FFmpeg 构建记录及许可证保存在输出前缀的 `share/ffmpeg/`。

配置已有 Android 构建时，传入脚本打印的 OpenSSL/curl 路径，并额外指定：

```bash
cmake -S . -B build/android/arm64-v8a \
    -DWITH_IOS_CONTROLLER=ON \
    -DMAA_IOS_FFMPEG_INCLUDE_DIR="$PWD/build/android-deps/out/include" \
    -DMAA_IOS_AVCODEC_LIBRARY="$PWD/build/android-deps/out/lib/libavcodec.so" \
    -DMAA_IOS_AVUTIL_LIBRARY="$PWD/build/android-deps/out/lib/libavutil.so" \
    -DMAA_IOS_SWSCALE_LIBRARY="$PWD/build/android-deps/out/lib/libswscale.so"
cmake --build build/android/arm64-v8a --config Debug --parallel 6
cmake --install build/android/arm64-v8a --config Debug --prefix build/android-install
```

首次配置仍需指定 NDK toolchain、`ANDROID_ABI=arm64-v8a`、`ANDROID_PLATFORM=android-24`
及 `MAADEPS_TRIPLET=maa-arm64-android`。运行包需包含 MaaFramework/MaaDeps 运行库和三个 FFmpeg 共享库；
使用此脚本的 FFmpeg 时，安装步骤会复制三个共享库与构建记录、许可证。
这条配方当前只支持 arm64，其他 ABI 需要各自构建依赖。手机端集成还需具备局域网访问权限；
软件解码的 CPU 占用、发热及持续帧率应在目标 Android 设备上评估。
