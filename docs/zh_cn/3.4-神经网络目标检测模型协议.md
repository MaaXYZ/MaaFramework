# 3.4 神经网络目标检测模型协议

本文档说明 `NeuralNetworkDetect` 使用的 ONNX 输入、输出张量协议和描述文件。Pipeline 字段参见[任务流水线协议](3.1-任务流水线协议.md#neuralnetworkdetect)。

## 模型包结构

模型和描述文件应放置在根目录的 `model/detect` 目录下：

```text
model/detect/
├── foo.onnx
└── foo.json
```

任务流水线使用包含扩展名的相对路径，例如 `"foo.onnx"`。用于描述模型的 `foo.json` 必须与 `foo.onnx` 位于同一文件夹下且同名。

描述文件不存在时，模型按[历史兼容协议](#无描述文件的兼容协议)加载。描述文件一旦存在，其 JSON、字段和张量契约必须全部有效，错误不会触发回退。

模型文件名用于区分不同导出文件；描述文件只声明输入和输出张量协议。

## 描述文件

完整 JSON Schema 位于 [`tools/neural-network-detector.schema.json`](../../tools/neural-network-detector.schema.json)。解析器拒绝未知字段。

```json
{
  "$schema": "https://raw.githubusercontent.com/MaaXYZ/MaaFramework/main/tools/neural-network-detector.schema.json",
  "input_protocol": {
    "type": "DirectResizeDivide255",
    "input_name": "images",
    "size": [640, 640]
  },
  "output_protocol": {
    "type": "DetrQueries",
    "boxes": "pred_boxes",
    "logits": "pred_logits",
    "activation": "Sigmoid",
    "top_k": 300
  },
  "labels": ["class_0"],
  "producer": {}
}
```

根对象字段：

- `input_protocol`: *object*  
    必选。声明图像输入和预处理协议。
- `output_protocol`: *object*  
    必选。声明输出张量协议。
- `labels`: *list<string>* | *object*  
    可选。字符串数组，或从 `"0"` 开始连续编号的类别 ID 到字符串的映射。标签必须非空且不能重复。
- `nms`: *string*  
    可选：`None`、`ClassAwareIoU` 或 `CandidateCoverage`。
- `nms_threshold`: *double*  
    可选，范围为 [0, 1]，默认 0.7。
- `$schema`: *string*  
    可选，仅供编辑器使用，不参与运行行为。
- `producer`: *object*  
    可选，仅记录导出来源，不参与运行行为。

## 通用输入限制

所有显式协议只接受 FP32、NCHW、RGB 三通道图像张量。运行时 batch 固定为 1；ONNX 可以声明静态 batch 1 或动态 batch，静态 batch 大于 1 会被拒绝。

静态 H/W 从 ONNX 张量签名读取。动态 H/W 必须通过 `input_protocol.size` 提供固定运行尺寸；`size` 的顺序为 `[width, height]`。显式填写的静态尺寸必须与 ONNX 一致。

不支持 NHWC、FP16、量化、灰度、自定义通道数、任意额外输入或多图 batch。

## 输入协议

所有输入协议都要求 `input_name` 与 ONNX 图像输入名称完全一致。

| `type` | 缩放 | 数值处理 | 适用模型 |
| --- | --- | --- | --- |
| `UltralyticsLetterbox` | 线性插值、保持比例、居中填充 114 | BGR 转 RGB、除以 255 | YOLOv8、YOLO11、YOLO26 |
| `DirectResizeDivide255` | 线性拉伸 | BGR 转 RGB、除以 255 | RT-DETR、D-FINE |
| `DirectResizeImageNet` | 线性拉伸 | BGR 转 RGB、除以 255，再按 ImageNet mean/std 标准化 | RF-DETR、LW-DETR |

ImageNet 参数固定为：

```text
mean = [0.485, 0.456, 0.406]
std  = [0.229, 0.224, 0.225]
```

每个 ROI 单独预处理和推理。坐标恢复后再增加该 ROI 在截图中的偏移。

### `original_size`

只有 `DetrPacked` 的 `Split` 布局允许且必须提供第二个输入：

```json
{
  "input_protocol": {
    "type": "DirectResizeDivide255",
    "input_name": "images",
    "size": [640, 640],
    "original_size": {
      "input_name": "orig_target_sizes",
      "order": "HW"
    }
  }
}
```

该输入必须为 INT64 `[1, 2]`，`order` 必须显式填写 `HW` 或 `WH`。数值是当前 ROI 的原始尺寸，不是整张截图的尺寸。

## 输出协议

框架不会根据输出名称、形状大小或模型品牌猜测协议。单张量协议要求模型恰好只有一个输出；`output_name` 可选，填写时必须匹配该输出。`DetrQueries` 和 `DetrPacked/Split` 必须按名称映射所有输出，而且模型不能包含未映射的额外输出。

### `YoloDense`

```json
{
  "output_protocol": {
    "type": "YoloDense",
    "layout": "ChannelsFirst",
    "output_name": "output0"
  }
}
```

- `ChannelsFirst`：FP32 `[1, 4 + C, N]`
- `ChannelsLast`：FP32 `[1, N, 4 + C]`
- 框：输入像素空间 `cxcywh`
- 分数：已激活的每类概率，无独立 objectness
- 每个 proposal 只保留最高分类别
- 默认 NMS：`ClassAwareIoU`

该协议适用于 YOLOv8、YOLO11 和非端到端的 YOLO26 导出。

### `YoloEndToEnd`

```json
{
  "output_protocol": {
    "type": "YoloEndToEnd",
    "output_name": "output0"
  }
}
```

- FP32 `[1, K, 6]`
- 每行是输入像素空间 `[x1, y1, x2, y2, score, class_id]`
- `class_id` 虽存放在浮点张量中，但必须是有限的非负整数
- 默认 NMS：`None`

该协议适用于默认端到端导出的 YOLO26。

### `DetrQueries`

```json
{
  "output_protocol": {
    "type": "DetrQueries",
    "boxes": "pred_boxes",
    "logits": "pred_logits",
    "activation": "Sigmoid",
    "top_k": 300
  }
}
```

- boxes：FP32 `[1, Q, 4]`，归一化 `cxcywh`
- logits：FP32 `[1, Q, C]`，或使用 `SoftmaxWithNoObject` 时为 `[1, Q, C + 1]`
- `activation`：`Sigmoid` 或 `SoftmaxWithNoObject`
- `SoftmaxWithNoObject` 把最后一个通道作为背景并排除
- 对 `Q × C` 的分类分数执行全局 Top-K，再应用置信度阈值
- `top_k` 可选，默认 300
- 默认 NMS：`None`

该协议适用于原始输出形式的 RT-DETR、RF-DETR、D-FINE 和 LW-DETR。具体导出文件的输出名称可能不同，必须按实际 ONNX 签名填写。

### `DetrPacked`

`Interleaved` 是单张量形式：

```json
{
  "output_protocol": {
    "type": "DetrPacked",
    "layout": "Interleaved",
    "output_name": "output0"
  }
}
```

- FP32 `[1, K, 6]`
- 每行是归一化 `[cx, cy, width, height, score, class_id]`
- 默认 NMS：`None`

`Split` 是已打包后处理的三张量形式：

```json
{
  "output_protocol": {
    "type": "DetrPacked",
    "layout": "Split",
    "labels": "labels",
    "boxes": "boxes",
    "scores": "scores"
  }
}
```

- labels：INT64 `[1, K]`
- boxes：FP32 `[1, K, 4]`，当前 ROI 像素空间 `xyxy`
- scores：FP32 `[1, K]`
- 必须同时配置 `input_protocol.original_size`
- 默认 NMS：`None`

`Split` 适用于把后处理一起导入图中的 RT-DETR 和 D-FINE。单张量 `[1, K, 6]` 的 DETR 变体使用 `Interleaved`，不另设协议名称。

## 模型映射

| 模型导出 | 输入协议 | 输出协议 |
| --- | --- | --- |
| YOLOv8、YOLO11 | `UltralyticsLetterbox` | `YoloDense` |
| YOLO26 默认端到端 | `UltralyticsLetterbox` | `YoloEndToEnd` |
| YOLO26 one-to-many | `UltralyticsLetterbox` | `YoloDense` |
| RT-DETR raw | `DirectResizeDivide255` | `DetrQueries` |
| RT-DETR deploy | `DirectResizeDivide255` | `DetrPacked/Split` |
| RF-DETR | `DirectResizeImageNet` | `DetrQueries` |
| D-FINE raw | `DirectResizeDivide255` | `DetrQueries` |
| D-FINE deploy | `DirectResizeDivide255` | `DetrPacked/Split` |
| LW-DETR | `DirectResizeImageNet` | `DetrQueries` |

该表描述常见官方导出，不是模型品牌白名单。最终必须以实际 ONNX 张量签名和导出配置为准。

## 标签

最终标签来源优先级：

1. Pipeline `labels`
2. 模型描述文件 `labels`
3. ONNX metadata
4. `Unknown_<class_id>`

ONNX metadata 按 `names`、`name`、`labels`、`class_names` 的顺序查找，接受 JSON 数组、JSON 对象和 Python 字典文本。对象键必须是从 0 开始连续的十进制类别 ID。

可从输出维度确定类别数时，标签数量必须完全匹配。无法静态确定类别数时，实际输出的类别 ID 仍必须落在已提供标签范围内。

## NMS、过滤和错误

NMS 配置优先级为 Pipeline、模型描述文件、输出协议默认值。`ClassAwareIoU` 只在同类别候选之间计算 IoU；`CandidateCoverage` 与类别无关，当交集面积达到低分候选面积乘阈值时抑制该低分候选。

每个 ROI 独立推理和 NMS，再合并结果；不会执行跨 ROI 全局 NMS。`expected` 在 NMS 后处理：非空时，每个期望类别只保留最高分结果；为空时保留全部合格结果。之后继续使用既有 `order_by`、负 `index`、结果排序和点击坐标语义。

协议、名称、类型、维度、batch、标签数量、非法类别 ID、非整数浮点类别 ID、非有限值和明显越界分数会产生识别 Error。Error 不受 `inverse` 影响，并立即进入当前节点的 `on_error`。越界框会被裁剪；空框、低分框和 NMS 抑制结果属于正常过滤。

## 无描述文件的兼容协议

没有同名 JSON 时使用 YOLOv8/YOLO11 兼容配置：

- 单个 FP32 `[1, 4 + C, N]` 输出
- `YoloDense/ChannelsFirst`
- 输入像素空间 `cxcywh`
- Stretch、`INTER_AREA`、RGB、除以 255
- 每个高于阈值的类别分数都形成候选
- `CandidateCoverage` NMS，默认阈值 0.7

该兼容路径用于已有 Maa YOLO Dense 模型。需要其他输入或输出协议时必须提供有效描述文件。
