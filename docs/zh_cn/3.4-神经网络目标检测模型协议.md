# 神经网络目标检测模型协议

`NeuralNetworkDetect` 通过 ONNX Runtime 加载目标检测模型。ONNX 模型文件提供张量结构和 metadata；同名 JSON 描述模型图中无法表达的图像预处理、输出解码和 NMS 语义。

## 1. 支持的行为

- 输入为一个三通道图像张量，可使用 RGB 或 BGR、NCHW 或 NHWC 布局；还可以增加一个表示原图尺寸的 INT64 `[1, 2]` 辅助输入。实际推理 batch 固定为 1，H/W 可以是静态或动态维度。
- 图像输入和浮点输出支持 FP32、FP16。预处理使用 FP32，FP16 输出会在解码前转换为 FP32。图输入输出仍为浮点类型的 QDQ INT8 模型可以直接使用。
- 输入处理支持拉伸、等比填充、颜色顺序转换、数值缩放、三通道 mean/std 标准化和 NCHW/NHWC 排列。
- 输出支持单个 ChannelsFirst/ChannelsLast 张量或多个 Split 张量，可组合框、分类分数、objectness、最终分数和分类下标等字段。
- 框支持 `CxCyWh`、`XyXy` 格式，以及输入图像坐标、归一化坐标和原始 ROI 坐标。分类分数支持无激活、Sigmoid、Softmax、objectness 相乘、no-object 通道和全局 top-k。
- NMS 支持 `None`、按类别执行 IoU 抑制的 `ClassAwareIoU`，以及兼容 Maa 既有行为的 `CandidateCoverage`。

每个 ROI 会分别完成预处理、推理、坐标恢复、数值检查和 NMS，再合并为 Pipeline 结果。`threshold`、`multi_label`、`expected`、`order_by` 和 `index` 的含义见 [Pipeline 协议中的 `NeuralNetworkDetect`](3.1-任务流水线协议.md#neuralnetworkdetect)。

## 2. 解析行为和配置优先级

对于 `foo.onnx`，框架会查找同目录下的 `foo.json`。最终协议按以下优先级解析：

1. **ModelProto**：输入输出名称、元素类型、shape 和静态输入尺寸。JSON 和 metadata 均不能覆盖这些内容。
2. **合法的 Ultralytics metadata**：用于确定输入处理、输出解码、NMS、动态输入尺寸和标签。
3. **JSON 显式步骤**：`input`、`output` 中带 `type` 的步骤。
4. **JSON preset**：展开为一组输入或输出步骤。
5. **步骤默认值**：显式步骤没有填写的参数使用该步骤的默认值。

metadata 和 JSON 可以描述同一项配置。metadata 能确定完整输入或输出协议时，该侧协议以 metadata 为准；冲突的完整 JSON 配置会被忽略并记录警告。metadata 中无法解析的字段会被视为缺失，JSON 可以补齐相应信息。例如，metadata 没有有效的 `imgsz` 时，可以使用 JSON 的 `Resize.size`；metadata 无法确定输出协议时，JSON 的 `output` 必须提供完整输出步骤。

JSON 必须符合 schema。未知字段、重复阶段、非法参数和不完整协议都会产生 `ModelError`。框架根据 ModelProto 自动匹配图像输入、辅助输入和输出张量；匹配不到或存在多组匹配时也会产生 `ModelError`。JSON 不能配置张量名称、元素类型、shape 或静态输入尺寸，也不会根据文件名或 shape 推测未知模型的处理语义。

动态输入的 width 和 height 分别按以下顺序确定：

1. ModelProto 中的静态维度；
2. Pipeline `input_size`；
3. Ultralytics metadata `imgsz`；
4. JSON `Resize.size`；
5. 当前 ROI 的尺寸。

`input_size` 和 `Resize.size` 均按 `[width, height]` 排列，只填充动态维度。使用当前 ROI 尺寸时不会自动进行 stride 对齐。

标签按 `Pipeline labels > metadata names > JSON labels > Unknown_<class_id>` 选择。Pipeline 和 JSON 标签支持字符串数组；JSON 还支持以从 0 连续编号的分类下标为键的对象。当输出能够确定类别数量时，标签数量必须与输出一致。

## 3. 可以省略 JSON 的情况

使用 [NNDetect 食谱](https://github.com/MaaXYZ/MaaNeuralNetworkCookbook/tree/main/NeuralNetworkDetect)，或通过 Ultralytics 的 [`model.export(format="onnx")`](https://docs.ultralytics.com/modes/export/) 导出模型时，如果 ONNX metadata 中 `author` 为 `Ultralytics`、`task` 为 `detect`，并且 `head` 为 `Detect` 或 `RTDETRDecoder`，模型可以不提供同名 JSON。

常见模型包括 YOLOv8、YOLO11、YOLO26，以及 Ultralytics 提供的 RT-DETR。框架会读取 `head`、`end2end`、`args.nms`、`imgsz` 和 `names` 等 metadata，并用 ModelProto 的输入输出契约验证自动生成的协议。

| metadata 能力 | 自动输入协议 | 自动输出协议 | NMS |
| --- | --- | --- | --- |
| `head=Detect`，Dense 输出 | `UltralyticsLetterbox` | `YoloDense` | `ClassAwareIoU`，阈值 0.7 |
| `head=Detect`，end-to-end 或导出时 `nms=true` | `UltralyticsLetterbox` | `YoloEndToEnd` | `None` |
| `head=RTDETRDecoder` | `Resize` | `DetrPacked`，归一化 `CxCyWh` | `None` |

对于 `Detect`，框架优先读取有效的 `end2end` 和 `args.nms`；这些字段不足以确定输出时，再使用 ModelProto 张量契约在 Dense 与 end-to-end 之间选择唯一匹配。YOLO26 的默认 end-to-end 输出和以 `end2end=false` 导出的 Dense 输出都可以自动解析。

上述自动识别范围内的模型通常不需要 JSON。即使提供 JSON，metadata 已确定的输入、输出和 NMS 语义仍然优先。下文中的 JSON 字段主要用于配置自动识别范围之外，或 metadata 缺失而无法形成完整协议的目标检测模型。

## 4. JSON 字段、preset 和参数覆盖

同名 JSON 的顶层结构如下：

```json
{
  "$schema": "https://raw.githubusercontent.com/MaaXYZ/MaaFramework/main/tools/neural-network-detector.schema.json",
  "input": [
    { "preset": "Resize" }
  ],
  "output": [
    { "preset": "YoloDense" }
  ],
  "nms": { "type": "ClassAwareIoU", "threshold": 0.7 },
  "labels": ["Cat", "Dog"]
}
```

| 字段 | 含义 |
| --- | --- |
| `$schema` | 可选的 schema 地址。 |
| `input` | 输入处理步骤数组。 |
| `output` | 输出张量映射和解码步骤数组。 |
| `nms` | NMS 类型及阈值。 |
| `labels` | 可选标签数组，或从分类 0 开始连续编号的对象。 |

### 4.1 preset 与显式步骤

`input` 和 `output` 各自最多包含一个 `preset`，每种 `type` 最多出现一次。框架不按照数组书写顺序执行，而是按固定阶段处理。解析时先展开 preset，再应用显式步骤，因此显式步骤会替换同类 preset 阶段。

替换以整个阶段为单位。显式步骤中未填写的参数使用该步骤自身的默认值，不继承 preset 中同阶段的参数。例如，`DetrQueries` 的 `ScoreDecode` 默认使用 Sigmoid；如果增加一个显式 `ScoreDecode` 来设置 `no_object_index`，仍需同时写出 `"activation": "Sigmoid"`，否则该显式阶段会采用默认的 `None`。

当 metadata 已经确定输入或输出协议时，metadata 的优先级高于 JSON 中的显式步骤和 preset。

### 4.2 输入步骤

| 阶段 | 参数 | 默认值 |
| --- | --- | --- |
| `Resize` | `mode`: `Stretch` / `Letterbox`；可选 `size`、`interpolation`、`fill`、`padding_position` | `Stretch`、`Linear`、填充值 114、`Center` |
| `Color` | `order`: `RGB` / `BGR` | `RGB` |
| `Scale` | `factor` | `1 / 255` |
| `Normalize` | 三通道 `mean`、`std` | 出现该阶段时两者必填 |
| `Layout` | `order`: `NCHW` / `NHWC` | `NCHW` |
| `AuxInput` | `kind`: `OriginalSize`；`order`: `HW` / `WH` | `OriginalSize`、`HW` |

输入 preset 展开如下：

| preset | 展开后的处理 |
| --- | --- |
| `UltralyticsLetterbox` | 等比居中填充 114、RGB、除以 255、NCHW |
| `Resize` | 直接拉伸、RGB、除以 255、NCHW |
| `ResizeIN` | `Resize`，再使用 ImageNet mean/std 标准化 |

不使用 preset 时，完整输入协议需要包含 `Resize`、`Color`、`Scale` 和 `Layout`。`Normalize` 和 `AuxInput` 按模型需要配置。

### 4.3 输出步骤

| 阶段 | 参数与作用 |
| --- | --- |
| `TensorMap` | `layout` 为 `ChannelsFirst`、`ChannelsLast` 或 `Split`；`fields` 声明张量中的字段角色。 |
| `BoxDecode` | `format` 为 `CxCyWh` 或 `XyXy`；`coordinates` 为 `Input`、`Normalized` 或 `Source`。 |
| `ScoreDecode` | 配置分类和 objectness 激活、相乘方式及 no-object 通道。 |
| `CandidateSelect` | 可选 `top_k`，用于全局候选选择。 |

`TensorMap.fields` 支持 `Boxes`、`ClassScores`、`Objectness`、`Score` 和 `ClassId`。协议必须包含 `Boxes`，评分字段使用以下一种组合：

- `ClassScores`，可以同时包含 `Objectness`；
- `Score` 与 `ClassId`。

`ChannelsFirst` 对应单个 `[1, F, N]` 浮点张量，`ChannelsLast` 对应单个 `[1, N, F]` 浮点张量。`Split` 为每个字段匹配一个独立张量，匹配依据是字段角色、元素类型和 shape，不依赖输出名称。`ClassId` 可以是 INT64，也可以是能精确表示非负整数的浮点值。

`BoxDecode.coordinates=Input` 和 `Normalized` 会按照输入预处理变换恢复到当前 ROI；`Source` 表示框已经使用当前 ROI 的原始坐标。

`ScoreDecode.activation` 支持 `None`、`Sigmoid`、`Softmax`；`objectness_activation` 支持 `None`、`Sigmoid`；`combine` 支持 `None`、`Multiply`。`no_object_index` 可以是 `First`、`Last` 或非负整数。Softmax 的分母仍包含 no-object 通道，输出时会跳过该通道并重新连续编号。`activation=None` 要求输入分数已经位于 `[0, 1]`。

`CandidateSelect.top_k` 必须是正整数。Pipeline `multi_label=true` 时，会在所有 proposal/query 与类别组合中执行全局 top-k；为 `false` 时，先为每个 proposal/query 选择最高分类别，再执行全局 top-k。已经带有 `ClassId` 的输出不受 `multi_label` 影响。候选选择完成后再执行 NMS，两者是独立阶段。

输出 preset 展开如下：

| preset | 展开后的处理 | 默认 NMS |
| --- | --- | --- |
| `YoloDense` | ChannelsFirst；`Boxes + ClassScores`；输入像素 `CxCyWh`；分数已激活 | `ClassAwareIoU`，阈值 0.7 |
| `YoloEndToEnd` | ChannelsLast；`Boxes + Score + ClassId`；输入像素 `XyXy` | `None` |
| `DetrQueries` | Split；`Boxes + ClassScores`；归一化 `CxCyWh`；Sigmoid；top-k 300 | `None` |
| `DetrPacked` | ChannelsLast；`Boxes + Score + ClassId`；归一化 `CxCyWh` | `None` |

不使用 preset 时，完整输出协议需要包含 `TensorMap`、`BoxDecode` 和 `ScoreDecode`。`CandidateSelect` 按模型需要配置。

### 4.4 NMS 和标签

`nms.type` 支持 `None`、`ClassAwareIoU`、`CandidateCoverage`。JSON 内部按“顶层 `nms` > 输出 preset 的默认 NMS > `None`”选择策略；自动识别得到的 metadata NMS 仍高于这三者。`ClassAwareIoU` 和 `CandidateCoverage` 的 `threshold` 默认值为 0.7。当 `type` 为 `None` 时，`threshold` 会被忽略。显式输出步骤不会清除输出 preset 附带的默认 NMS，需要通过顶层 `nms` 修改。

`labels` 可以写成数组：

```json
{ "labels": ["Cat", "Dog"] }
```

也可以写成从 0 开始连续编号的对象：

```json
{ "labels": { "0": "Cat", "1": "Dog" } }
```

标签不能为空或重复；metadata `names` 与 JSON `labels` 冲突时使用 metadata，并记录警告。

## 5. RF-DETR 参考配置

RF-DETR 导出的 ONNX 通常包含图像输入，以及分别表示框和分类分数的 `dets`、`labels` 输出。框架会使用这些张量的元素类型和 shape 验证协议，但 `rfdetr_notes`、张量名称和 shape 本身不足以确定预处理、坐标格式、分数激活和候选选择方式，因此需要同名 JSON。

以 RF-DETR Nano 为例，假设模型文件为 `model/detect/rfdetr_nano.onnx`，可创建 `model/detect/rfdetr_nano.json`：

```json
{
  "$schema": "https://raw.githubusercontent.com/MaaXYZ/MaaFramework/main/tools/neural-network-detector.schema.json",
  "input": [
    { "preset": "ResizeIN" }
  ],
  "output": [
    { "preset": "DetrQueries" },
    { "type": "ScoreDecode", "activation": "Sigmoid", "no_object_index": "Last" }
  ],
  "nms": { "type": "None" }
}
```

对应的 Pipeline 节点可以写为：

```jsonc
{
  "recognition": "NeuralNetworkDetect",
  "model": "rfdetr_nano.onnx",
  "multi_label": false,
  "threshold": 0.3
}
```

各项配置的含义如下：

- `ResizeIN` 提供直接拉伸、RGB、除以 255 和 ImageNet mean/std 标准化。
- `DetrQueries` 提供 Split `Boxes + ClassScores`、归一化 `CxCyWh`、Sigmoid 和 top-k 300。
- 显式 `ScoreDecode` 替换 preset 中的同名阶段，在保留 Sigmoid 的同时将最后一个分类通道标记为 no-object。
- `nms=None` 表示不进行外部 NMS；该值也是 `DetrQueries` 的默认 NMS，保留在示例中用于明确模型行为。
- `multi_label=false` 先为每个 query 选择最高分类别，再执行全局 top-k。`threshold` 继续由 Pipeline 控制。

该 JSON 依靠 ModelProto 自动匹配 `dets` 和 `labels`，无需也不能填写输出张量名称。缺少完整 `input` 或 `output` 协议时，模型加载会返回 `ModelError`。不同 RF-DETR 导出版本的图契约可能不同，配置仍需与实际模型的输入输出保持一致。
