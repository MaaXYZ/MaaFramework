# 运行证据采集

`MaaTaskerSetOption` 支持实例级采集设置，不修改其它 Tasker 或全局 DebugMode。未设置的原图、标注图和数量选项继续采用既有全局行为；配置快照默认关闭，字节预算默认不限制。

| 选项 | 值类型 | 行为 |
| --- | --- | --- |
| `MaaTaskerOption_RecoImageRaw` | `bool` | 保留本次识别输入的 PNG 原图 |
| `MaaTaskerOption_RecoImageDraws` | `bool` | 生成识别标注图，覆盖全局和 Debug 构建的默认设置 |
| `MaaTaskerOption_RecoImageCacheLimit` | `MaaSize` | 按识别 ID 保留的图片组数量，0 禁用缓存 |
| `MaaTaskerOption_RecoImageCacheBytes` | `MaaSize` | 原图及标注图编码后的总字节预算，0 禁用缓存 |
| `MaaTaskerOption_CaptureConfig` | `bool` | 在识别及动作通知中附带实际使用的配置 |

数量和字节预算同时生效。超出预算时先淘汰最早的图片；单个图片组超过总字节预算时跳过该组，保留其它已有图片。设置本地预算会立即清理超出部分，`MaaTaskerClearCache` 清除所有历史图片。预算只限制缓存中的编码图片，不包含正在执行的图像、临时副本和事件配置。全局数量设置保持原有兼容行为。

建议在提交任务前完成设置。原图通过既有 `MaaTaskerGetRecognitionDetail` 的 `raw` 输出读取，标注图通过 `draws` 输出读取。事件中的 `reco_details.image_status` 描述写入缓存时的情况：`available`、`not_captured`、`disabled`、`budget_exceeded` 或 `unavailable`。这是当时的状态，不是永久保留凭证。`MaaTaskerGetRecognitionImageStatus(tasker, reco_id, buffer)` 查询当前保留状态，额外可能返回 `evicted`；ID 无效或已被 ClearCache 清理则返回 false。Python 的 `get_recognition_image_status` / NodeJS 的 `recognition_image_status` 在查询失败时返回 None/null，结果没有租约语义。

消费者应在完成通知中查询并复制需要的图片，再异步编码归档或写盘。关闭缓存、超过预算、后续识别以及显式清理都可能让查询不再得到图片；并发操作没有额外的图片保留锁。回调中的字符串和 Context 句柄只借用，不得保存后跨线程继续调用。

开启配置采集后，`Node.Recognition.*` 和 `Node.Action.*` 通知增加可选的 `pipeline` 对象，它来自该次操作使用的 `PipelineData`，包含默认值及已应用的 override。Starting 和对应终态使用同一份快照。它不同于事后调用 `MaaContextGetNodeData` 读取当前配置；识别回调中修改配置，会影响后续动作的快照，但不会改写已开始识别的快照。快照中的动态 ROI/target 引用仍保持配置形式，实际解析位置以识别/动作结果为准；它不包含模型或图片文件字节。

Python 使用实例方法 `set_reco_image_raw`、`set_reco_image_draws`、`set_reco_image_cache_count`、`set_reco_image_cache_bytes`、`set_capture_config`。现有静态方法 `Tasker.set_reco_image_cache_limit` 仍设置全局默认值。NodeJS 对应实例属性 `reco_image_raw`、`reco_image_draws`、`reco_image_cache_count`、`reco_image_cache_bytes`、`capture_config`；64 位预算使用十进制字符串。MaaAgent 的远程 Tasker 支持相同设置。
