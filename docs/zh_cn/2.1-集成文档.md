### 单独使用 ControlUnit

C++ 项目可以直接链接某个控制器后端。将 SDK 安装目录和配套 MaaDeps 的开发包目录（含 Boost、OpenCV）加入 `CMAKE_PREFIX_PATH`。下面的配置将 Windows 后端链接到 `my_app`。

```cmake
find_package(MaaFramework CONFIG REQUIRED COMPONENTS MaaWin32ControlUnit)
target_link_libraries(my_app PRIVATE MaaFramework::MaaWin32ControlUnit)
```

包含 `<MaaControlUnit/Win32ControlUnitAPI.h>`，用 `MaaWin32ControlUnitCreate` 创建控制器，通过返回的指针调用 `connect()`、`screencap()` 等方法，最后用 `MaaWin32ControlUnitDestroy` 释放。其他后端使用各自的同名 CMake 目标，例如 `MaaFramework::MaaAdbControlUnit`。只有当前平台实际构建的后端才会导出，可用 `if(TARGET MaaFramework::MaaWin32ControlUnit)` 判断。

后端目标会传递公共 C++ 接口库 `MaaFramework::MaaControlUnit`。自行用 `LoadLibrary` 或 `dlopen` 加载后端的程序也可以只链接这个公共目标，并通过 `<MaaControlUnit/MaaControlUnitAPI.h>` 使用接口声明。接口传递 `std::string` 和 `cv::Mat`，下游需使用与 SDK 兼容的 C++ 运行库和 OpenCV。

部署时，将同一 SDK 中的公共库（Windows 上为 `MaaControlUnit.dll`）、所选后端及其运行时依赖一起放入动态库搜索路径。若宿主自行编译 MaaUtils，使用对应 MaaFramework 版本锁定的 MaaUtils 提交，确保后端依赖的工具函数齐全。升级已有安装时，一并更新使用中的 MaaFramework 和后端，确保它们从同一公共库获取接口的运行时类型信息（RTTI）。
