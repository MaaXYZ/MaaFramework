# 4.1 Build Guide

> [!TIP]
> _You only need to read this chapter if you are ready to develop MaaFramework itself. If you only want to develop applications based on MaaFramework, please refer to [Quick Start](1.1-QuickStarted.md)._

Before you start, ensure Git, Python 3, and CMake 3.24+ are installed, along with the toolchain for your platform (Windows: MSVC 2022; Linux/macOS: Ninja + g++/clang).

## Local Development

1. Clone the repo with all submodules (recommended)  
    Submodules contain third-party dependencies and must be initialized before building. You can re-run this step anytime to keep them in sync.

    ```sh
    git clone --recurse-submodules https://github.com/MaaXYZ/MaaFramework.git
    ```

    or

    ```sh
    git clone https://github.com/MaaXYZ/MaaFramework.git
    cd MaaFramework
    git submodule update --init --recursive
    ```

2. Download prebuilt MaaDeps

    ```sh
    python3 tools/maadeps-download.py
    ```

    The script downloads and verifies the prebuilt dependencies. If the network is unstable, simply rerun it.

3. Configure CMake preset  
    - Windows

    ```bash
    cmake --preset "MSVC 2022"
    ```

    - Linux

    ```bash
    # Run one of the following:
    cmake --preset "NinjaMulti Linux x64"
    # Or
    cmake --preset "NinjaMulti Linux arm64"
    ```

    - macOS

    ```bash
    cmake --preset "NinjaMulti"
    ```

4. Build and install

    ```bash
    cmake --build build --config Release
    cmake --install build --prefix install
    ```

Switch `--config` to `Debug`/`RelWithDebInfo` as needed. Binaries and related files are placed in the `install` directory by default.

For more details, refer to [Build CI](https://github.com/MaaXYZ/MaaFramework/blob/main/.github/workflows/build.yml).

## iOS video streaming on an Android host

Android arm64 hosts can use iOS `Stream` capture through FFmpeg software decoding; MediaCodec is not used.
Without target FFmpeg libraries, builds can still use `ScreenshotService` only.
Discovery reports capture methods according to the shared protocol target's compiled capabilities.

Prepare an Android NDK, arm64 Android MaaDeps and `make`. From the repository root:

```bash
export ANDROID_NDK_ROOT=/path/to/android-ndk
export ANDROID_API=24
export WORK_DIR="$PWD/build/android-deps/src"
bash tools/ios-android-deps.sh -j 6 "$PWD/build/android-deps/out"
```

The script downloads pinned, checksum-verified OpenSSL, curl and FFmpeg sources.
FFmpeg enables HEVC/PNG decoding and pixel conversion only, producing `libavcodec.so`, `libavutil.so`
and `libswscale.so`, without GPL/nonfree components. Source archives remain in `WORK_DIR`;
FFmpeg build records and its license are stored under the output prefix's `share/ffmpeg/`.

For an existing Android build, supply the OpenSSL/curl paths printed by the script and add:

```bash
cmake -S . -B build/android/arm64-v8a \
    -DWITH_IOS_CONTROLLER=ON \
    -DMAA_IOS_FFMPEG_INCLUDE_DIR="$PWD/build/android-deps/out/include" \
    -DMAA_IOS_AVCODEC_LIBRARY="$PWD/build/android-deps/out/lib/libavcodec.so" \
    -DMAA_IOS_AVUTIL_LIBRARY="$PWD/build/android-deps/out/lib/libavutil.so" \
    -DMAA_IOS_SWSCALE_LIBRARY="$PWD/build/android-deps/out/lib/libswscale.so"
cmake --build build/android/arm64-v8a --config Debug --parallel 6
cmake --install build/android/arm64-v8a --config Debug --prefix build/android-install
```

A fresh configuration also requires the NDK toolchain, `ANDROID_ABI=arm64-v8a`,
`ANDROID_PLATFORM=android-24` and `MAADEPS_TRIPLET=maa-arm64-android`.
Include the MaaFramework/MaaDeps runtime and all three FFmpeg shared libraries when deploying.
For FFmpeg built by this script, installation copies its shared libraries, build records and license.
This recipe currently targets arm64 only; other ABIs require their own dependency builds.
Android applications also need LAN access permissions. Evaluate CPU use, heat and sustained frame rate on the target device.
