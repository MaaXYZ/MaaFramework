# 4.1 Build Guide

> [!TIP]
> _You only need to read this chapter if you are ready to develop MaaFramework itself. If you only want to develop applications based on MaaFramework, please refer to [Quick Start](1.1-QuickStarted.md)._

Before you start, ensure Git, Python 3, and CMake 3.24+ are installed, along with the toolchain for your platform (Windows: MSVC 2022; Linux/macOS: Ninja + g++/clang).

## Local Development

1. Clone the repo with all submodules (recommended)  
    Submodules contain third-party dependencies and must be initialized before building. You can re-run this step anytime to keep them in sync.

    ```sh
    git clone --recurse-submodules https://github.com/MaaXYZ/MaaFramework.git
    ```

    or

    ```sh
    git clone https://github.com/MaaXYZ/MaaFramework.git
    cd MaaFramework
    git submodule update --init --recursive
    ```

2. Download prebuilt MaaDeps

    ```sh
    python3 tools/maadeps-download.py
    ```

    The script downloads and verifies the prebuilt dependencies. If the network is unstable, simply rerun it.

3. Configure CMake preset  

    The iOS controller is enabled by default; see [Building iOS support](#building-ios-support). Pass `-DWITH_IOS_CONTROLLER=OFF` to disable it.
    - Windows

    ```bash
    cmake --preset "MSVC 2022"
    ```

    - Linux

    ```bash
    # Run one of the following:
    cmake --preset "NinjaMulti Linux x64"
    # Or
    cmake --preset "NinjaMulti Linux arm64"
    ```

    - macOS

    ```bash
    cmake --preset "NinjaMulti"
    ```

4. Build and install

    ```bash
    cmake --build build --config Release
    cmake --install build --prefix install
    ```

Switch `--config` to `Debug`/`RelWithDebInfo` as needed. Binaries and related files are placed in the `install` directory by default.

For more details, refer to [Build CI](https://github.com/MaaXYZ/MaaFramework/blob/main/.github/workflows/build.yml).

## Building iOS support

The iOS controller is enabled by default; pass `-DWITH_IOS_CONTROLLER=OFF` to disable it. Fetch the pinned XDeviceBridge revision with `git submodule update --init --recursive`. MaaFramework builds only its lightweight client; no OpenSSL, curl, FFmpeg or other phone protocol dependencies are downloaded or compiled here.

```bash
cmake -S . -B build -DBUILD_IOS_TEST=ON
cmake --build build --config RelWithDebInfo
ctest --test-dir build -C RelWithDebInfo -R '^MaaIOS' --output-on-failure
```

Retain normal MaaDeps/toolchain arguments for your platform. Installation includes MaaIOSControlUnit and xdb_client shared libraries. Install the complete xdb desktop runtime using the [XDeviceBridge installation guide](https://github.com/scrctl/XDeviceBridge/blob/main/docs/INSTALL.md) and pair/prepare DDI through its CLI/SDK; clients automatically start the background server when needed. Windows/Linux/macOS/Android use the same client protocol. Android Apps embed xdb_server and own its data directory, permissions and lifecycle; see XDeviceBridge for backend dependency builds and packaging.

Tests cover input mapping and the real framework C ABI against a deterministic xdb peer: discovery, video/PNG/fallback, geometry and input. They access no phone and do not establish device or Android App runtime acceptance.
