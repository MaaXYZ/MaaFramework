# 4.1 Build Guide

> [!TIP]
> _You only need to read this chapter if you are ready to develop MaaFramework itself. If you only want to develop applications based on MaaFramework, please refer to [Quick Start](1.1-QuickStarted.md)._

Before you start, ensure Git, Python 3, and CMake 3.24+ are installed, along with the toolchain for your platform (Windows: MSVC 2022; Linux/macOS: Ninja + g++/clang).

## Local Development

1. Clone the repo with all submodules (recommended)  
    Submodules contain third-party dependencies and must be initialized before building. You can re-run this step anytime to keep them in sync.

    ```sh
    git clone --recurse-submodules https://github.com/MaaXYZ/MaaFramework.git
    ```

    or

    ```sh
    git clone https://github.com/MaaXYZ/MaaFramework.git
    cd MaaFramework
    git submodule update --init --recursive
    ```

2. Download prebuilt MaaDeps

    ```sh
    python3 tools/maadeps-download.py
    ```

    The script downloads and verifies the prebuilt dependencies. If the network is unstable, simply rerun it.

3. Configure CMake preset  

    The iOS controller is disabled by default. To enable it, prepare its extra dependencies as described in [Building iOS support](#building-ios-support) and pass `-DWITH_IOS_CONTROLLER=ON`.
    - Windows

    ```bash
    cmake --preset "MSVC 2022"
    ```

    - Linux

    ```bash
    # Run one of the following:
    cmake --preset "NinjaMulti Linux x64"
    # Or
    cmake --preset "NinjaMulti Linux arm64"
    ```

    - macOS

    ```bash
    cmake --preset "NinjaMulti"
    ```

4. Build and install

    ```bash
    cmake --build build --config Release
    cmake --install build --prefix install
    ```

Switch `--config` to `Debug`/`RelWithDebInfo` as needed. Binaries and related files are placed in the `install` directory by default.

For more details, refer to [Build CI](https://github.com/MaaXYZ/MaaFramework/blob/main/.github/workflows/build.yml).

## Building iOS support

The iOS controller is disabled by default; enable it with `-DWITH_IOS_CONTROLLER=ON`. Before configuring CMake, prepare these target-compatible dependencies in addition to MaaDeps:

| Dependency | Purpose and requirements |
| --- | --- |
| OpenSSL | Pairing, cryptography and USB/Wi-Fi authentication |
| FFmpeg (optional) | `avcodec`, `avutil`, `swscale`, with HEVC/PNG decoding and pixel conversion |
| libcurl | HTTPS for DDI downloads and ticket requests; macOS uses the SDK's libcurl |
| pugixml | plist XML parsing |
| lwIP, mDNS | User-space tunnel networking and device discovery |

JSON handling uses the bundled meojson library. pugixml can be supplied as a CMake package; otherwise its sources, like lwIP and mDNS, are fetched using pinned URLs and hashes.
Set `-DMAA_IOS_FETCH_DEPENDENCIES=OFF` to disable these CMake downloads. Supply a pugixml package or
`FETCHCONTENT_SOURCE_DIR_PUGIXML`, plus `FETCHCONTENT_SOURCE_DIR_LWIP` and `FETCHCONTENT_SOURCE_DIR_MDNS`.
OpenSSL and non-macOS libcurl must be built or installed beforehand; the same applies to FFmpeg when used. CMake does not download these libraries automatically.

### Using the repository dependency recipes

[`tools/ios/ci/dependencies.py`](../../tools/ios/ci/dependencies.py) builds dependencies from the repository's vcpkg manifest and generates `framework.cmake` for framework configuration.
`--platform` accepts `windows`, `linux`, `macos` or `android`; `--architecture` accepts `x86_64` or `aarch64`.
Download MaaDeps for the target first and prepare a bootstrapped vcpkg checkout, pinned to the
`builtin-baseline` in [`tools/ios/ci/vcpkg.json`](../../tools/ios/ci/vcpkg.json).

Run this example from the repository root on Apple Silicon macOS:

```bash
git clone https://github.com/microsoft/vcpkg.git build/ios-vcpkg
git -C build/ios-vcpkg checkout e456309491fd875487bf02b8a0dca76c1b1b00cc
build/ios-vcpkg/bootstrap-vcpkg.sh -disableMetrics
python3 tools/ios/ci/dependencies.py \
    --vcpkg "$PWD/build/ios-vcpkg" \
    --work "$PWD/build/ios-dependencies" \
    --platform macos --architecture aarch64
cmake -C build/ios-dependencies/framework.cmake --preset NinjaMulti \
    -DWITH_IOS_CONTROLLER=ON
cmake --build build --config Release --parallel
cmake --install build --config Release --prefix install
```

On Windows, use `bootstrap-vcpkg.bat`. Select the corresponding platform, architecture and framework CMake preset for other targets.
Linux recipes use the MaaDeps target toolchain and sysroot. Android recipes require `ANDROID_NDK_ROOT` and use API 24.
The macOS framework and dependencies built by this recipe target 13.3. Homebrew libraries built for newer systems do not establish 13.3 compatibility.
Cross-compilation must use target libraries without mixing in host dependencies.

With iOS disabled by default, framework configuration skips iOS-specific dependency lookup and downloads. Explicit `-DWITH_IOS_CONTROLLER=ON` requires the mandatory dependencies and C++ threading features; missing requirements fail configuration instead of automatically disabling the controller.
The framework, Toolkit and PiCli load `MaaIOSControlUnit` at runtime. Disabling this build option does not disable their APIs: a compatible backend library and its runtime dependencies enable iOS support; operations fail when the backend is absent.
FFmpeg is detected automatically when available. Set `-DMAA_IOS_USE_FFMPEG=OFF` to skip its lookup and linkage.
Without FFmpeg, macOS retains VideoToolbox video decoding but loses the software fallback; Windows, Linux and Android retain `ScreenshotService` only. Discovery reports the capture methods supported by the build.
The dependency recipes and official CI builds include FFmpeg for full video support.

### Tests and distribution packages

- `-DBUILD_IOS_TEST=ON` builds controller, Toolkit and protocol offline tests.
- After building, run `ctest --test-dir build -C Release --output-on-failure`. Offline tests do not replace real-device acceptance.
- The framework [`build.yml`](../../.github/workflows/build.yml) builds and packages dependencies for Windows, Linux, macOS and Android.
  [`test.yml`](../../.github/workflows/test.yml) runs native and Python iOS offline tests on Windows x64, Linux x64 and macOS arm64.
- For distribution, [`tools/ios/ci/package.py`](../../tools/ios/ci/package.py) writes runtime libraries, licenses and provenance under `bin/licenses/ios/` in `--output`; when `--source-output` is specified (pointing to a separate directory), it also collects corresponding sources, build recipes and build metadata (excluding `test/TestingDataSet`).
  `build.yml` uploads binary artifacts as `MAA-*` and source artifacts as `ios-source-*`; `release.yml` publishes them as separate ZIP files. Binary manifests identify the matching source artifact. SDK packagers download only binary artifacts.
  See `build.yml`'s `Collect iOS runtime dependencies and source materials` steps for arguments and call order.

## iOS video streaming on an Android host

Android arm64 hosts can use iOS `Stream` capture through FFmpeg software decoding; MediaCodec is not used.
Without target FFmpeg libraries, builds can still use `ScreenshotService` only.
Discovery reports capture methods according to the shared protocol target's compiled capabilities.

Prepare an Android NDK, arm64 Android MaaDeps and `make`. From the repository root:

```bash
export ANDROID_NDK_ROOT=/path/to/android-ndk
export ANDROID_API=24
export WORK_DIR="$PWD/build/android-deps/src"
bash tools/ios/android-deps.sh -j 6 "$PWD/build/android-deps/out"
```

The script downloads pinned, checksum-verified OpenSSL, curl and FFmpeg sources.
FFmpeg enables HEVC/PNG decoding and pixel conversion only, producing `libavcodec.so`, `libavutil.so`
and `libswscale.so`, without GPL/nonfree components. Source archives remain in `WORK_DIR`;
FFmpeg build records and its license are stored under the output prefix's `share/ffmpeg/`.

For an existing Android build, supply the OpenSSL/curl paths printed by the script and add:

```bash
cmake -S . -B build/android/arm64-v8a \
    -DWITH_IOS_CONTROLLER=ON \
    -DMAA_IOS_FFMPEG_INCLUDE_DIR="$PWD/build/android-deps/out/include" \
    -DMAA_IOS_AVCODEC_LIBRARY="$PWD/build/android-deps/out/lib/libavcodec.so" \
    -DMAA_IOS_AVUTIL_LIBRARY="$PWD/build/android-deps/out/lib/libavutil.so" \
    -DMAA_IOS_SWSCALE_LIBRARY="$PWD/build/android-deps/out/lib/libswscale.so"
cmake --build build/android/arm64-v8a --config Debug --parallel 6
cmake --install build/android/arm64-v8a --config Debug --prefix build/android-install
```

A fresh configuration also requires the NDK toolchain, `ANDROID_ABI=arm64-v8a`,
`ANDROID_PLATFORM=android-24` and `MAADEPS_TRIPLET=maa-arm64-android`.
Include the MaaFramework/MaaDeps runtime and all three FFmpeg shared libraries when deploying.
For FFmpeg built by this script, installation copies its shared libraries, build records and license.
This recipe currently targets arm64 only; other ABIs require their own dependency builds.
Android applications also need LAN access permissions. Evaluate CPU use, heat and sustained frame rate on the target device.
