# Runtime evidence capture

`MaaTaskerSetOption` supports instance-scoped capture without modifying other Taskers or global DebugMode. Unset raw-image, draw and count options preserve existing global behavior. Configuration capture is off by default and the default byte budget is unlimited.

| Option | Value type | Behavior |
| --- | --- | --- |
| `MaaTaskerOption_RecoImageRaw` | `bool` | Retain the recognition input as a PNG |
| `MaaTaskerOption_RecoImageDraws` | `bool` | Generate annotation images, overriding global and Debug-build defaults |
| `MaaTaskerOption_RecoImageCacheLimit` | `MaaSize` | Number of image groups retained by recognition ID; zero disables retention |
| `MaaTaskerOption_RecoImageCacheBytes` | `MaaSize` | Total encoded bytes of raw and annotation images; zero disables retention |
| `MaaTaskerOption_CaptureConfig` | `bool` | Include the effective configuration in recognition/action notifications |

Count and byte budgets both apply. Oldest image groups are evicted first. A group larger than the entire byte budget is omitted without evicting existing groups. Setting an instance budget immediately evicts excess entries; `MaaTaskerClearCache` clears image history. Budgets cover cached encoded images, not active image processing, temporary copies or event configuration. The global count setting retains its previous behavior.

Configure options before posting tasks. Read raw and annotation images through the existing `raw` and `draws` outputs of `MaaTaskerGetRecognitionDetail`. Event `reco_details.image_status` describes cache insertion: `available`, `not_captured`, `disabled`, `budget_exceeded` or `unavailable`. This is a historical observation, not a retention lease. `MaaTaskerGetRecognitionImageStatus(tasker, reco_id, buffer)` queries current retention and may additionally report `evicted`. It returns false for invalid or cleared IDs. Python `get_recognition_image_status` / NodeJS `recognition_image_status` returns None/null when unavailable. The query does not retain the image.

Consumers should query and copy images during completion notifications, then archive or write them asynchronously. Disabled caching, exhausted budgets, later recognitions and explicit cache clearing can make images unavailable. There is no additional retention lock against concurrent operations. Callback strings and Context handles are borrowed and must not be retained for later calls from another thread.

With configuration capture enabled, `Node.Recognition.*` and `Node.Action.*` include an optional `pipeline` object dumped from the actual `PipelineData` used by that operation, including defaults and applied overrides. Starting and its terminal notification share the same snapshot. A recognition callback that overrides the pipeline changes a subsequent action's snapshot, not the recognition's existing snapshot. Dynamic ROI/target references remain in configuration form; recognition/action results describe resolved positions. Model and image file contents are not included.

Python instance methods are `set_reco_image_raw`, `set_reco_image_draws`, `set_reco_image_cache_count`, `set_reco_image_cache_bytes` and `set_capture_config`. Existing static `Tasker.set_reco_image_cache_limit` continues to set the global default. NodeJS uses instance properties `reco_image_raw`, `reco_image_draws`, `reco_image_cache_count`, `reco_image_cache_bytes` and `capture_config`; 64-bit budgets are decimal strings. Remote Taskers through MaaAgent support the same options.
