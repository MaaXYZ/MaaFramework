### Using a ControlUnit directly

A C++ project can link a controller backend directly. Add the SDK installation prefix and the matching MaaDeps development prefix (containing Boost and OpenCV) to `CMAKE_PREFIX_PATH`. For the Windows backend, use the following CMake targets.

```cmake
find_package(MaaFramework CONFIG REQUIRED COMPONENTS MaaWin32ControlUnit)
target_link_libraries(my_app PRIVATE MaaFramework::MaaWin32ControlUnit)
```

Include `<MaaControlUnit/Win32ControlUnitAPI.h>`, create the controller with `MaaWin32ControlUnitCreate`, call methods such as `connect()` and `screencap()` through the returned pointer, and release it with `MaaWin32ControlUnitDestroy`. Other backends export their own CMake targets, such as `MaaFramework::MaaAdbControlUnit`. Use `if(TARGET MaaFramework::MaaWin32ControlUnit)` to check whether your SDK was built with a particular backend.

Each backend target links the shared C++ interface library `MaaFramework::MaaControlUnit` transitively. Applications that load backends with `LoadLibrary` or `dlopen` can link just this common target and include `<MaaControlUnit/MaaControlUnitAPI.h>` for the API declarations. The interfaces pass `std::string` and `cv::Mat` across library boundaries, so use a C++ runtime and OpenCV build compatible with the SDK.

Deploy the common library (`MaaControlUnit.dll` on Windows), the selected backend from the same SDK, and its runtime dependencies on the dynamic library search path. Hosts that build MaaUtils themselves should use the MaaUtils revision pinned by their MaaFramework release so that all backend imports are available. When upgrading an existing installation, update any MaaFramework and backend binaries together so that they share the same runtime type information (RTTI).
