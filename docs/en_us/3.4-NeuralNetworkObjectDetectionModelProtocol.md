# 3.4 Neural-network object-detection model protocol

This document defines the ONNX input and output tensor protocols and same-name model descriptor used by `NeuralNetworkDetect`. See the [Pipeline protocol](3.1-PipelineProtocol.md#neuralnetworkdetect) for Pipeline fields.

## Model package structure

The model and descriptor should be placed in the root `model/detect` directory:

```text
model/detect/
├── foo.onnx
└── foo.json
```

The Pipeline uses a relative path including the extension, such as `"foo.onnx"`. The descriptor `foo.json` must be in the same directory as `foo.onnx` and use the same base name.

When the descriptor is absent, MaaFramework uses the [legacy compatibility protocol](#compatibility-protocol-without-a-descriptor). Once a descriptor exists, its JSON, fields, and tensor contract must all be valid; errors never trigger legacy fallback.

Model filenames distinguish export files; the descriptor only declares their input and output tensor protocols.

## Descriptor

The complete JSON Schema is [`tools/neural-network-detector.schema.json`](../../tools/neural-network-detector.schema.json). The parser rejects unknown fields.

```json
{
  "$schema": "https://raw.githubusercontent.com/MaaXYZ/MaaFramework/main/tools/neural-network-detector.schema.json",
  "input_protocol": {
    "type": "DirectResizeDivide255",
    "input_name": "images",
    "size": [640, 640]
  },
  "output_protocol": {
    "type": "DetrQueries",
    "boxes": "pred_boxes",
    "logits": "pred_logits",
    "activation": "Sigmoid",
    "top_k": 300
  },
  "labels": ["class_0"],
  "producer": {}
}
```

Root fields:

- `input_protocol`: *object*  
    Required. Declares the image input and preprocessing protocol.
- `output_protocol`: *object*  
    Required. Declares the output tensor protocol.
- `labels`: *list<string>* | *object*  
    Optional string array or mapping from contiguous class IDs beginning at `"0"` to strings. Labels must be non-empty and unique.
- `nms`: *string*  
    Optional: `None`, `ClassAwareIoU`, or `CandidateCoverage`.
- `nms_threshold`: *double*  
    Optional, in [0, 1], default 0.7.
- `$schema`: *string*  
    Optional editor hint; ignored at runtime.
- `producer`: *object*  
    Optional export provenance; ignored at runtime.

## Common input restrictions

Every explicit protocol accepts only an FP32, NCHW, three-channel RGB image tensor. Runtime batch is fixed to 1. The ONNX signature may declare static batch 1 or a dynamic batch; a static batch greater than 1 is rejected.

Static H/W are read from the ONNX tensor signature. Dynamic H/W require a fixed runtime `input_protocol.size`, ordered as `[width, height]`. A supplied size must match any static ONNX dimensions.

NHWC, FP16, quantized, grayscale, custom-channel, arbitrary-extra-input, and multi-image-batch models are unsupported.

## Input protocols

Every input protocol requires `input_name` to match the ONNX image input exactly.

| `type` | Resize | Numeric conversion | Common models |
| --- | --- | --- | --- |
| `UltralyticsLetterbox` | Linear, aspect-preserving, centered padding 114 | BGR to RGB, divide by 255 | YOLOv8, YOLO11, YOLO26 |
| `DirectResizeDivide255` | Linear stretch | BGR to RGB, divide by 255 | RT-DETR, D-FINE |
| `DirectResizeImageNet` | Linear stretch | BGR to RGB, divide by 255, then ImageNet mean/std | RF-DETR, LW-DETR |

The fixed ImageNet values are:

```text
mean = [0.485, 0.456, 0.406]
std  = [0.229, 0.224, 0.225]
```

Each ROI is preprocessed and inferred independently. The ROI's screenshot offset is added after coordinate restoration.

### `original_size`

Only `DetrPacked` with the `Split` layout permits and requires a second input:

```json
{
  "input_protocol": {
    "type": "DirectResizeDivide255",
    "input_name": "images",
    "size": [640, 640],
    "original_size": {
      "input_name": "orig_target_sizes",
      "order": "HW"
    }
  }
}
```

This input must be INT64 `[1, 2]`, and `order` must explicitly be `HW` or `WH`. Its values are the current ROI's original dimensions, not the full screenshot dimensions.

## Output protocols

MaaFramework does not infer protocols from output names, dimension sizes, or model brands. Single-tensor protocols require exactly one model output. Their optional `output_name`, when supplied, must match it. `DetrQueries` and `DetrPacked/Split` require explicit mappings for every output, and the model may not contain unmapped extra outputs.

### `YoloDense`

```json
{
  "output_protocol": {
    "type": "YoloDense",
    "layout": "ChannelsFirst",
    "output_name": "output0"
  }
}
```

- `ChannelsFirst`: FP32 `[1, 4 + C, N]`
- `ChannelsLast`: FP32 `[1, N, 4 + C]`
- Boxes: input-pixel `cxcywh`
- Scores: already-activated per-class probabilities, without separate objectness
- Only the highest-scoring class is retained per proposal
- Default NMS: `ClassAwareIoU`

This protocol fits YOLOv8, YOLO11, and non-end-to-end YOLO26 exports.

### `YoloEndToEnd`

```json
{
  "output_protocol": {
    "type": "YoloEndToEnd",
    "output_name": "output0"
  }
}
```

- FP32 `[1, K, 6]`
- Each row is input-pixel `[x1, y1, x2, y2, score, class_id]`
- Although stored in a float tensor, `class_id` must be a finite non-negative integer
- Default NMS: `None`

This protocol fits default end-to-end YOLO26 exports.

### `DetrQueries`

```json
{
  "output_protocol": {
    "type": "DetrQueries",
    "boxes": "pred_boxes",
    "logits": "pred_logits",
    "activation": "Sigmoid",
    "top_k": 300
  }
}
```

- boxes: FP32 `[1, Q, 4]`, normalized `cxcywh`
- logits: FP32 `[1, Q, C]`, or `[1, Q, C + 1]` with `SoftmaxWithNoObject`
- `activation`: `Sigmoid` or `SoftmaxWithNoObject`
- `SoftmaxWithNoObject` treats the final channel as background and removes it
- A global Top-K is applied over `Q × C` class scores before confidence filtering
- `top_k` is optional and defaults to 300
- Default NMS: `None`

This protocol fits raw-output RT-DETR, RF-DETR, D-FINE, and LW-DETR exports. Output names vary by export, so use the actual ONNX signature.

### `DetrPacked`

`Interleaved` is the single-tensor form:

```json
{
  "output_protocol": {
    "type": "DetrPacked",
    "layout": "Interleaved",
    "output_name": "output0"
  }
}
```

- FP32 `[1, K, 6]`
- Each row is normalized `[cx, cy, width, height, score, class_id]`
- Default NMS: `None`

`Split` is the three-tensor, postprocessed form:

```json
{
  "output_protocol": {
    "type": "DetrPacked",
    "layout": "Split",
    "labels": "labels",
    "boxes": "boxes",
    "scores": "scores"
  }
}
```

- labels: INT64 `[1, K]`
- boxes: FP32 `[1, K, 4]`, current-ROI-pixel `xyxy`
- scores: FP32 `[1, K]`
- `input_protocol.original_size` is required
- Default NMS: `None`

`Split` fits RT-DETR and D-FINE exports that include postprocessing. Single-tensor DETR `[1, K, 6]` variants use `Interleaved`; there is no separate protocol name.

## Model mapping

| Model export | Input protocol | Output protocol |
| --- | --- | --- |
| YOLOv8, YOLO11 | `UltralyticsLetterbox` | `YoloDense` |
| Default end-to-end YOLO26 | `UltralyticsLetterbox` | `YoloEndToEnd` |
| YOLO26 one-to-many | `UltralyticsLetterbox` | `YoloDense` |
| RT-DETR raw | `DirectResizeDivide255` | `DetrQueries` |
| RT-DETR deploy | `DirectResizeDivide255` | `DetrPacked/Split` |
| RF-DETR | `DirectResizeImageNet` | `DetrQueries` |
| D-FINE raw | `DirectResizeDivide255` | `DetrQueries` |
| D-FINE deploy | `DirectResizeDivide255` | `DetrPacked/Split` |
| LW-DETR | `DirectResizeImageNet` | `DetrQueries` |

This table describes common official exports, not a model-brand allowlist. The actual ONNX tensor signature and export configuration are authoritative.

## Labels

Final label priority is:

1. Pipeline `labels`
2. Model descriptor `labels`
3. ONNX metadata
4. `Unknown_<class_id>`

ONNX metadata keys are tried in this order: `names`, `name`, `labels`, `class_names`. JSON arrays, JSON objects, and Python dictionary text are accepted. Object keys must be contiguous decimal class IDs beginning at zero.

When the output dimensions determine the class count, the label count must match exactly. If the class count is not known statically, actual output class IDs must still be within any supplied label table.

## NMS, filtering, and errors

Effective NMS priority is Pipeline, model descriptor, then output-protocol default. `ClassAwareIoU` computes IoU only between candidates of the same class. `CandidateCoverage` is class-independent and suppresses a lower-scoring candidate when the intersection reaches its area multiplied by the threshold.

Each ROI is inferred and suppressed independently before results are merged; no cross-ROI global NMS is performed. `expected` is applied after NMS. When non-empty, only the highest-scoring result for each expected class remains; when empty, all qualifying results remain. Existing `order_by`, negative `index`, result ordering, and click-coordinate semantics then apply unchanged.

Protocol, name, type, dimension, batch, label-count, invalid-class-ID, non-integral-float-class-ID, non-finite-value, and clearly out-of-range-score failures produce a recognition Error. Error is not affected by `inverse` and immediately enters the current node's `on_error`. Out-of-bounds boxes are clipped; empty, low-score, and NMS-suppressed boxes are normal filtering outcomes.

## Compatibility protocol without a descriptor

When no same-name JSON exists, MaaFramework strictly retains the historical configuration:

- One FP32 `[1, 4 + C, N]` output
- `YoloDense/ChannelsFirst`
- Input-pixel `cxcywh`
- Stretch with `INTER_AREA`, RGB, and divide by 255
- Every class score above the threshold creates a candidate
- `CandidateCoverage` NMS with default threshold 0.7

This compatibility path supports existing Maa YOLO Dense models. Any other input or output protocol requires a valid descriptor.
